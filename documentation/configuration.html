About the .env file

All environment-specific settings live in a single .env file at the project root. The file is read once at boot and exposed through the env() helper. The shipped .env.example file is an up-to-date reference - never ship an example file with real secrets.

Important. The .env file must be outside the web server's served directory, or at least hidden by .htaccess. The bundled .htaccess already blocks direct access to any file matching .env*. Double-check by visiting https://your-domain.example/.env - you should receive a 403 response.

SMS

Transactional SMS (order confirmation, dispatch alert, 2FA fallback) is optional. Three drivers are shipped:

  • log - writes SMS bodies to storage/logs/sms.log. Ideal for development.
  • netgsm - Turkish carrier integration using the Netgsm HTTP API.
  • twilio - global provider using the Twilio REST API.
KeyDefaultDescriptionRequired
SMS_DRIVERlogOne of log, netgsm, twilio.No
SMS_API_KEY(empty)Driver-specific API key. For Twilio it is the auth token; for Netgsm it is the password.If driver is not log
SMS_USER(empty)Account identifier (Netgsm user code or Twilio Account SID).If driver is not log
SMS_SENDER(empty)Sender ID displayed on the recipient handset. Must be pre-approved by the carrier.If driver is not log

Payment gateways

The order checkout flow can be set to either "Cash on delivery" (default) or an online gateway. The bundled integration is an Iyzico placeholder. You can swap in Stripe, PayTR or any other gateway by extending OdemeService.

KeyDefaultDescriptionRequired
PAYMENT_DRIVERcashSupported values: cash, iyzico.No
IYZICO_MODEsandboxsandbox points to Iyzico's test environment; production uses the live endpoint.If driver is iyzico
IYZICO_API_KEY(empty)API key from the Iyzico merchant panel.If driver is iyzico
IYZICO_SECRET(empty)Secret key from the Iyzico merchant panel.If driver is iyzico
Where to get Iyzico keys. Register a merchant account at iyzico.com, complete the KYC flow, and retrieve your sandbox keys from Settings → Merchant → Credentials. Live keys are issued only after account verification.

Two-factor authentication (admin)

2FA is off by default and is enabled per administrator account. The flow is TOTP-based (Google Authenticator, Authy, 1Password) with ten single-use backup codes generated at setup.

  1. Log in to the admin panel.
  2. Go to Settings → Security → 2FA.
  3. Scan the QR code with your authenticator app.
  4. Enter the 6-digit code to verify. The system then shows your backup codes once - download or print them.

Putting it all together

After any change to .env, the application reloads the new values on the next request - no restart required. However, caching and OPcache may hold on to old values. If you hit an unexpected issue, clear storage/cache/ and, if OPcache is active, restart PHP-FPM or Apache.

rm -rf storage/cache/*
sudo systemctl reload php8.2-fpm # or apache2
