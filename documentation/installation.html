System requirements

Please confirm your hosting environment matches the minimums below before uploading the archive. Shared hosting with cPanel is supported as long as shell access or a file manager with extraction is available.

PHP8.18.2 or 8.3Required extensions: pdo_mysql, mbstring, json, openssl, gd, fileinfo, intl.
MySQL8.08.0.36+MariaDB 10.6+ is also supported. Use utf8mb4 character set.

Pre-flight checklist

  • You have an SFTP or SSH account to upload files, or cPanel File Manager access.
  • You have a MySQL user with CREATE, ALTER, INDEX, SELECT, INSERT, UPDATE, DELETE, DROP on the target database.
  • Your domain name already resolves to the server.
  • You can edit .htaccess or the virtual host configuration.
  • You have a valid TLS certificate (Let's Encrypt is fine). The platform should not be run over plain HTTP in production.

Step-by-step installation

Step 1 - Download and extract

Download the archive from your CodeCanyon account. The download is a single zip file typically named pastane-v1.0.zip. Unzip it locally and review the top-level folders.

unzip pastane-v1.0.zip -d pastane
cd pastane
ls -la

You should see folders such as admin/, api/, assets/, bin/, config/, database/, docs/, documentation/, includes/, menu/, src/, storage/, uploads/, vendor/.

Step 2 - Create the database

Log in to MySQL as a privileged user and execute:

CREATE DATABASE pastane_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'pastane_user'@'localhost' IDENTIFIED BY 'replace-with-strong-password';
GRANT ALL PRIVILEGES ON pastane_db.* TO 'pastane_user'@'localhost';
FLUSH PRIVILEGES;

Write down the database name, user, and password - you will need them in Step 3.

Step 3 - Configure the environment file

Copy the example file and open it in your favourite editor.

cp .env.example .env
nano .env

At minimum you must fill in the following keys. Full reference is in the Configuration chapter.

APP_ENV=production
APP_URL=https://your-domain.example
APP_DEBUG=false

DB_HOST=127.0.0.1
DB_NAME=pastane_db
DB_USER=pastane_user
DB_PASS=replace-with-strong-password

JWT_SECRET=generate-a-long-random-string
METRICS_TOKEN=generate-another-long-random-string
Tip. Generate strong secrets with php -r "echo bin2hex(random_bytes(32));" or openssl rand -hex 32. Never commit the .env file to source control.

Step 4 - Install or refresh PHP dependencies (optional)

The archive already ships with a production-ready vendor/ folder. If you prefer to regenerate it, for example to apply security patches, run:

composer install --no-dev --optimize-autoloader

For development machines where you want test tooling available:

composer install

Step 5 - Run database migrations

The platform uses explicit migrations so that upgrades are predictable. Two options are available.

Option A (recommended): run the migration runner from the command line.

php bin/migrate.php

Option B: import the single SQL snapshot that ships with the package. Use this if your host does not permit CLI PHP.

mysql -u pastane_user -p pastane_db < database.sql
Note. Mixing the two options is not recommended. Pick one and stick to it.

Step 6 - Seed demo data (optional)

An idempotent seed script creates five categories, fifteen demo products, ten tables with unique QR tokens, and a single administrator account. Re-running the script is safe; it will not create duplicates.

php bin/db-seed.php

The script prints the generated administrator password to standard output and also writes it to storage/logs/db-seed.log. Copy it somewhere safe immediately; it is not displayed again.

Step 7 - Web server configuration

On Apache, confirm the following modules are enabled:

sudo a2enmod rewrite
sudo a2enmod headers
sudo systemctl reload apache2

The project ships an .htaccess that hardens headers, redirects HTTP to HTTPS, and sets DirectoryIndex index.php. Make sure AllowOverride All is set for the vhost, otherwise the file is ignored.

Typical virtual host snippet:

<VirtualHost *:443>
  ServerName your-domain.example
  DocumentRoot /var/www/pastane

  <Directory /var/www/pastane>
    AllowOverride All
    Require all granted
  </Directory>

  SSLEngine on
  SSLCertificateFile    /etc/letsencrypt/live/your-domain.example/fullchain.pem
  SSLCertificateKeyFile /etc/letsencrypt/live/your-domain.example/privkey.pem
</VirtualHost>

Step 8 - File permissions

The application writes to storage/ (logs, cache, sessions, backups) and uploads/ (product images). Grant the web server user write access while keeping everything else read-only.

sudo chown -R www-data:www-data /var/www/pastane
sudo find /var/www/pastane -type d -exec chmod 755 {} \;
sudo find /var/www/pastane -type f -exec chmod 644 {} \;
sudo chmod -R 775 /var/www/pastane/storage /var/www/pastane/uploads
Never run chmod -R 777. It is insecure and unnecessary. If you encounter write errors, verify ownership first (chown), not permissions.

Step 9 - First administrator login

Open your browser and navigate to https://your-domain.example/admin/login.php. Use the credentials printed during Step 6. If you skipped the seed, create a user manually with the SQL below.

-- Replace 'choose-a-password' with your chosen password.
INSERT INTO admin_kullanicilar (kullanici_adi, sifre, rol, aktif)
VALUES (
  'admin',
  -- Hash generated at runtime:
  -- php -r "echo password_hash('choose-a-password', PASSWORD_BCRYPT, ['cost' => 12]);"
  '$2y$12$PLACEHOLDER_PUT_REAL_HASH_HERE',
  'admin',
  1
);
Success. If the dashboard loads and shows today's (likely empty) statistics, the core installation is complete. Head over to the Configuration chapter to wire up email, SMS and payment.

Troubleshooting

Symptom: "404 Not Found" on every page except the homepage

Apache mod_rewrite is disabled, or AllowOverride is not set to All. Re-read Step 7 and reload Apache. Run a2enmod rewrite and verify with apachectl -M | grep rewrite.

Symptom: "Access denied for user" during first page load

The database credentials in .env are wrong or the user does not have rights to the database. Reconnect with the same credentials from the command line to verify (mysql -u pastane_user -p pastane_db).

Symptom: "Failed to open stream: Permission denied" in storage/logs/

The web server user cannot write to storage/. Re-run the chown commands from Step 8. Do not use chmod 777.

Symptom: CSS and images are missing

Most often caused by an incorrect APP_URL or a misconfigured virtual host document root. Verify that https://your-domain.example/assets/css/style.css returns HTTP 200 directly from your browser. If it does not, your document root is pointing at the wrong folder.

Symptom: "Class not found" errors

The Composer autoload map is stale. Run composer dump-autoload -o. If Composer is unavailable on the server, upload a fresh vendor/ folder from a machine that has it.

Symptom: "Too many redirects"

Either your reverse proxy is adding an HTTPS redirect while .htaccess also redirects, or APP_URL contains http:// while the server serves HTTPS. Fix one or the other. For CDN users, the CDN should forward X-Forwarded-Proto: https.

Uninstalling

If for any reason you wish to remove the platform, drop the database and delete the document root. There are no system-wide files installed outside the archive.

mysql -u root -p -e "DROP DATABASE pastane_db;"
sudo rm -rf /var/www/pastane
